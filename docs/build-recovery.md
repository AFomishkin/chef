# Восстановление сборки unit-тестов

`chef test unit <extension> --build-recovery individual --build-recovery-retries 3 --build-recovery-timeout-ms 120000`

Режимы: `off` — одна сборка; `exclude` — исключать только входной файл, однозначно
указанный диагностикой; `individual` — дополнительно пробовать файлы по отдельности
при неоднозначной ошибке. По умолчанию используется `individual`.

Общий бюджет на цель: три дополнительные сборки и 120000 мс после первой ошибки.
Уже начатая сборка завершается. Ноль запрещает дополнительные сборки.
При неоднозначной ошибке в 600 файлах стандартного бюджета хватит максимум на три
пофайловые попытки. Остальные файлы отмечаются непроверенными. Бюджет можно явно увеличить.

При `--debug` или `--cdp-port` режим `individual` ограничивается режимом `exclude`:
одна отладочная сессия работает с одним бандлом. Неоднозначная ошибка останавливает
восстановление. Повторная ошибка без расположения, если ни одна отдельная сборка
не была успешной, также останавливает его без обвинения входных файлов.

Успешные бандлы исполняются один раз. Ошибки assertions не запускают восстановление.
Ошибка браузера или выполнения останавливает оставшиеся бандлы; их файлы перечислены
в ошибке прогона. `--list` выводит здоровые тесты без исполнения и сохраняет ошибки сборки.

JSON `extensions[].details.unit.buildRecovery` с `schemaVersion: 1` содержит режим,
лимиты, число попыток, время восстановления, исключённые и непроверенные файлы,
структурированные ошибки `UNIT_BUILD_FAILED`. Пути относительны корню пакета.
Причины остановки: `complete`, `disabled`, `ambiguous`, `retry-limit`, `time-limit`.
`complete` не означает успешный прогон: ошибки сборки остаются красными результатами.
Непроверенные файлы — потеря покрытия, а не упавшие assertions.
Опции применимы только к unit-тестам. Поддержка обозначена в CLI help как `protocol v1`.
